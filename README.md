# دوري وثاق

تطبيق ويب لدوري كرة قدم افتراضي بين 4 فرق (15 أسبوعًا، عملة "وثاق"، إعارات لاعبين بالتفاوض المباشر بين الكباتن).
مبني بـ HTML/CSS/JS بسيط منظم + Supabase (قاعدة بيانات + مصادقة + Realtime).

## 1) إعداد مشروع Supabase

1. أنشئ حسابًا ومشروعًا جديدًا على https://supabase.com
2. من **SQL Editor**، شغّل ملف `supabase/run_once.sql` كاملًا مرة واحدة (يجمع كل ملفات `supabase/migrations/` بالترتيب). لو شغّلته قبل وأضيف ملف ترحيل جديد لاحقًا، شغّل الملف الجديد فقط بدل إعادة الملف الكامل (تجنبًا لأخطاء "already exists").
3. من **Settings → API**، انسخ **Project URL** و **anon public key**، وضعهما في [`js/supabaseClient.js`](js/supabaseClient.js).
4. **مهم**: تأكد من تعطيل "Confirm email" إن وجدته في Authentication → Sign In / Providers → Email (بعض إصدارات لوحة Supabase لا تعرضه إطلاقًا — في هذه الحالة تجاهل هذه الخطوة، وأنشئ كل حساب بالطريقة اليدوية في الخطوة التالية فقط، لأن التسجيل الذاتي من داخل التطبيق سيصطدم بحد إرسال البريد "email rate limit" بدون هذا الإعداد).

## 2) إنشاء الحسابات (المدير والكباتن)

الطريقة الموثوقة الوحيدة حاليًا: من لوحة Supabase مباشرة (وليس من داخل التطبيق):

1. **Authentication → Users → Add user → Create new user**.
2. **Email**: رقم الجوال بدون الصفر الأول + `@wathaq.local` — مثال: الرقم `0538811009` يصير `538811009@wathaq.local`.
3. **Password**: أي كلمة مرور (6 خانات على الأقل).
4. فعّل ✅ **Auto confirm user** (ضروري — بدونه الحساب يبقى غير مفعّل).
5. اضغط **Create user**، وانسخ الـ **UID** الذي يظهر.
6. من **SQL Editor**، رقّ الحساب حسب دوره:
   ```sql
   -- لحساب مدير:
   update profiles set role = 'super_admin', team_id = null, display_name = 'الاسم'
   where id = '<UID>';

   -- لحساب كابتن فريق:
   update profiles set role = 'team_captain', team_id = '<uuid الفريق>', display_name = 'اسم الكابتن'
   where id = '<UID>';
   ```
   (يمكن الحصول على `uuid` الفريق من صفحة `admin/teams.html` أو من جدول `teams` في Table Editor.)

بعدها يسجّل صاحب الحساب دخوله من `login.html` برقم جواله وكلمة المرور مباشرة — بدون أي خطوة إضافية من طرفه.

## 3) تشغيل التطبيق محليًا

التطبيق ملفات ثابتة بالكامل، يكفي أي خادم ملفات ثابت:
```bash
python3 -m http.server 8080
```
ثم افتح `http://localhost:8080`. (لو عدّلت أي ملف ولم تظهر التغييرات، جرّب تحديثًا كاملًا للمتصفح — قد يكون محفوظًا مؤقتًا/Cache.)

## آلية إعارة اللاعبين (بدون مزايدة)

التفاوض مع اللاعب يتم **خارج التطبيق بالكامل** (واتساب أو أي وسيلة). بعد الاتفاق:
1. كابتن أحد الفريقين المشاركين في مباراة الأسبوع يسجّل الصفقة من صفحة تلك المباراة: يختار اللاعب والمبلغ المتفق عليه.
2. تظهر الصفقة للجميع باسم اللاعب والفريق المستعير فقط — **المبلغ يبقى مخفيًا** إلا عن المدير والفريقين المعنيين مباشرة (المستعير وصاحب اللاعب الأصلي).
3. المدير يراجع الصفقات المسجَّلة من **الإدارة → صفقات الإعارة** ويعتمد الصحيحة (لو سجّل فريقان نفس اللاعب لنفس المباراة، اعتماد أحدهما يرفض الآخر تلقائيًا).
4. بعد الاعتماد، يمثّل اللاعب الفريق المستعير في تلك المباراة فقط، ثم يعود تلقائيًا لفريقه الأصلي بعدها.
5. القاعدة المالية ثابتة: المبلغ يُخصم من المستعير ويُضاف لصاحب اللاعب الأصلي **فقط إذا فاز المستعير بالمباراة**؛ لا خصم إن خسر.

**افتراض يحتاج تأكيدك**: تسجيل صفقة على لاعب لمباراة معيّنة مقصور على الفريقين المشاركين في تلك المباراة فقط (دالة `claim_player_loan` في [`supabase/migrations/0011_loan_claims.sql`](supabase/migrations/0011_loan_claims.sql)) — إن كان القصد فتحها لأي فريق حتى لو غير مشارك في تلك المباراة، أخبرني لتعديلها.
